# 房源带看风险识别 Demo

这个程序用于识别可能发生“房源已经签约或下架，但经纪人仍按原计划到场”的带看预约。

程序会读取历史带看数据，用已有的 `is_completed` 结果自动计算风险规律，再为没有结果的记录生成：

- 未完成风险分数
- 风险等级（低、中、高）
- 风险原因
- 建议动作

## 为什么采用可解释评分

样本中最明显的信号是房源状态的新鲜度：状态同步时间距离带看时间越久，带看未完成率越高。可预约时段、日浏览量、区域和房源类型作为辅助信号。

评分使用历史分组失败率，并做少量平滑处理，避免某个样本很少的分组产生极端结论。整个实现只使用 Go 标准库，便于阅读、运行和后续调整。

## 数据结论

去掉完全重复记录后，数据中有 1,286 条带看记录，其中 1,238 条有结果，48 条需要评分：

| 数据分组 | 样本数 | 未完成率 |
| --- | ---: | ---: |
| 状态在 15 分钟内同步 | 893 | 3.25% |
| 状态超过 15 分钟未同步 | 345 | 40.87% |

固定 8:2 留出集回测中，对中高风险记录进行干预需要覆盖 30.38% 的预约，可以召回 79.41% 的历史失败记录，干预命中率为 34.18%。这说明“先处理状态较旧的预约”能够用有限的确认成本覆盖大部分风险。

## 运行方式

```powershell
go run . -input "C:\Users\18790\Downloads\inspections.csv" -output risk_results.csv
```

默认只给 `is_completed` 为空的记录评分。如果希望查看所有记录的风险，可增加：

```powershell
go run . -input "C:\Users\18790\Downloads\inspections.csv" -output all_results.csv -score-all
```

## 输出字段

输出会保留原始字段，并增加：

| 字段 | 含义 |
| --- | --- |
| `sync_age_minutes` | 带看时间与最近状态同步时间的间隔（分钟） |
| `risk_score` | 预计带看未完成的概率，范围为 0～1 |
| `risk_level` | `低风险`、`中风险` 或 `高风险` |
| `risk_reasons` | 触发风险的主要原因 |
| `recommended_action` | 建议业务动作 |

当前处置规则：

- 高风险（风险分数不低于 35%）：暂停带看，先由房源维护人确认房源仍可交易。
- 中风险（风险分数不低于 20%）：立即刷新房源状态，并请经纪人在出发前确认。
- 低风险：正常提醒，并在带看前再次自动校验。

## 数据处理说明

- `is_completed=1` 表示带看已完成，`0` 表示未完成，空值表示待评分。
- 时间按 RFC3339 解析，能够正确处理 `+08:00` 和 `Z` 等不同时区。
- 完全重复的 `inspection_id` 只保留一条，避免重复样本影响统计结果。
- 同一个 `inspection_id` 如果内容冲突，程序会直接报错，避免静默使用错误数据。
- 程序启动时会做一次固定规则的留出集回测，并打印风险拦截率、失败召回率和命中率。

## 使用限制

现有数据的结果字段只有 `is_completed`。它能表示带看是否完成，但不能区分“房源已签约或下架”“客户临时取消”“经纪人迟到”等不同原因。因此当前分数应理解为“带看未完成风险”，不能直接当成“房源已经失效的概率”。

正式上线时建议增加 `failure_reason` 或单独的 `property_invalid` 标签，并记录状态刷新、人工确认及最终房源状态。获得这些数据后，再专门训练房源失效风险模型。

## 后续落地建议

在线系统可在“预约创建后”和“经纪人出发前”各调用一次评分。中高风险预约应触发房源状态刷新；高风险预约在确认前不应继续发送正常带看提醒。生产环境还应持续记录最终结果，定期重新校准风险分组。
